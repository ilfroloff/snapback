# Architecture

Static structure: what the pieces are and how they connect. For the rules on
*building new things*, see [PATTERNS.md](PATTERNS.md); for the Claude Code
session model, see [DOMAIN.md](DOMAIN.md).

## Identity

`snapback` (short alias `sb`) is a single self-contained Rust binary: a
[ratatui](https://ratatui.rs) TUI that browses, searches, and resumes **Claude
Code** sessions stored as JSONL under `~/.claude/projects/`, plus the board
actions that need no teardown — quick reply (`Ctrl-R`), interrupt (`Ctrl-K`) and
the `Ctrl-N` draft's background launch.
It exists because the built-in `/resume` picker is per-project with no cross-folder
view and no content search. It depends on nothing outside its own `Cargo.toml`.

That last sentence still holds despite `npm/` existing. The npm package is a
**distribution channel, not a dependency**: it carries prebuilt binaries and
copies one onto your `PATH`. The installed program is the same self-contained
Rust binary, with no node anywhere near it. Nothing under `src/` may ever import,
shell out to, or assume node.

One **dev-dependency**, `nucleo` (`=0.5.0`): the membership ORACLE the parity test
in `src/search.rs` compares this crate's match set against. It is reachable from
`mod tests` alone, so the shipped binary carries no matcher but `memchr` — a
runtime `use nucleo` anywhere would undo that.

All versions are pinned **exact** for reproducibility (see `Cargo.toml`
comments). `Cargo.lock` is committed. Edition 2021. The toolchain is pinned
exact too — `rust-toolchain.toml` names `1.95.0` + `rustfmt`/`clippy`, and it is
the single source of truth for local dev AND CI (rustup reads it locally,
`actions-rust-lang/setup-rust-toolchain` reads it in the workflows), so "stable"
can never silently move under a lint gate.

## Module map

Data-core-first: the `store` layer's parsing core (`discover` / `parse` /
`command` / `group` / `label` / `lineage`) is framework-independent and fully unit-tested
before any TUI code runs on top of it. **`store::preview` is a deliberate exception**: it
returns styled ratatui `Text` because it *is* the rendering step (transcript →
markdown), colocated with the store since its output is cached per session and
fitted to the pane width.

So the invariant is not "`store` is framework-pure" — that would be false, and
this crate ships exactly one frontend, so decoupling the renderer would buy
nothing. The invariant that earns its keep is narrower: **a module whose job is
PARSING never owns a palette; only a module whose job is RENDERING reaches for
the render framework.** That is why `agents::classify` buckets the undocumented
`state`/`status` value set while `tui::view` maps that bucket to a `Color`.

| Module | File(s) | Responsibility |
| --- | --- | --- |
| `run` | `src/lib.rs` | Crate root + persistent-dashboard loop: parse args, load store, run the board, spawn `claude` on resume, recover a lost liveness race (`after_nonzero_resume`), reload, repeat. Hidden `--print-list` dump. `src/main.rs` and `src/bin/sb.rs` are thin shims that only call `run`. |
| `cli` | `src/cli.rs` | Argument parsing (`--all`/`-a`, `--project`/`-p`, `--help`/`-h`, hidden `--print-list`); resolves the canonical launch dir. Hand-rolled — no `clap`, no arg-parsing dependency at all — as one `match` per argument; no flag takes a value, and an unknown one is ignored. There is no model flag: a model is only ever picked inside a compose box (`Ctrl-L`, see `tui::compose`). The two scope flags are mutually exclusive in meaning but not in syntax — the LAST one on the command line wins (the plain single-pass assignment, so an alias carrying `-p` stays overridable by a trailing `-a`). `-a` carries a SECOND, orthogonal meaning that precedence does not touch: `Args::all_scope_enabled`, which is what puts the all scope on the `Ctrl-A` cycle and is the only route to it. |
| `store` | `src/store/mod.rs` | Data core entry: `Session` model + the `SessionStore` reload pipeline; sorts repo→branch→timestamp-desc. **STATEFUL**, and the one cache in the crate that is not derived state: it owns a store root and an in-memory `path -> (FileStamp, Option<Session>)` map (`None` a sidecar read to the end), so `reload` re-parses only the files whose `(mtime, len)` moved and hands back a `Reload` naming which sessions it re-read. Discovery is never cached (see [the load pipeline](#the-load-pipeline-store)). `load{,_from}` remain as one-shot wrappers over an empty cache, for `--print-list` and tests. |
| `store::discover` | `src/store/discover.rs` | Store-root resolution + depth-pinned file enumeration (the subagent-exclusion rule). |
| `store::parse` | `src/store/parse.rs` | Fail-soft, streaming per-file JSONL scan → `ParsedFile`. Its one per-record DECISION is the failed-background-task flag: the pure `task_signal` classifies each record as a `failed` notice (set, a later one replacing), the user's own prompt (clear), or neither, and the pass applies it in file order — see [DOMAIN.md](DOMAIN.md#failed-background-task-storeparse). The same pass feeds `label::FirstPrompt` every record and builds the content index, which leaves injected records out and keeps a slash command as `/name args` (`store::command::typed_text`) — see [DOMAIN.md](DOMAIN.md#content-index-storeparse). |
| `store::group` | `src/store/group.rs` | `repo_of(cwd)` repo/branch grouping heuristic (worktree collapse). A PURE string function — it never asks git, which is what keeps the collapse a property of the path alone; the git-backed answer is `worktrees`' job. |
| `store::label` | `src/store/label.rs` | Label preference (summary → first prompt the user wrote → session id). That middle tier is `FirstPrompt`, fed every record in file order: a typed prompt, or a PROMPT COMMAND labelled `/name args` — a slash-command wrapper held for exactly one record and confirmed when the next is an injected body whose `parentUuid` points back at it (a local command is followed by its output instead, and stays skipped). Also the SHARED HOME of the per-record reads more than one surface must agree on: `is_sidechain` (the store's "not from a subagent" read, used by the label pick and by `parse`'s failed-task flag; `store::preview` keeps an inline copy of it), `is_meta`, the peer gate `peer_origin`, and `is_injected` — `isMeta` and not a peer message — the ONE "Claude Code injected this" check the preview's injected node, the content index and the label all call (see [DOMAIN.md](DOMAIN.md#injected-context-node-storepreview)). |
| `store::command` | `src/store/command.rs` | Claude Code's control-wrapper tags, parsed ONCE for three consumers, framework-free: the `CONTROL_WRAPPERS` allowlist, the pure `collapse_control_wrappers` → `Segment`s (literal / command / marker, a marker carrying its raw text), and `command_text`, the one `/name args` normalisation. The preview draws the segments, the content index keeps a command as `/name args` and every other byte as written (`typed_text`), and the label reads a body that is one command and nothing else (`sole_command`) — so the `▷` line, the index and the label hold identical text. |
| `store::lineage` | `src/store/lineage.rs` | Background-fork lineage identity + folding: `lineage_key` (`(repo, branch, root_uuid)`), `head_of` (the newest member), `group_members` (partition any index set into conversations — the grouping the header's counter and `tui::app::child_indices` share, so a row drawn as a child can never be counted as a conversation of its own; a rootless session is a lineage of one). That is the rule's SHARED home, not its ONLY one: THREE grouping loops read `lineage_key` in this module, and the other two — `fold` and `lost_agent_bindings` — each hand-roll a keyed `HashMap<LineageKey, Vec<usize>>` because both need the KEY itself, which `group_members` throws away. A change to the grouping rule must be mirrored across all three. Also here: `root_of` (the OLDEST DATED member — the far end of the SAME `member_rank` ordering `head_of` takes the top of, filtered to dated members first because `Reverse(None)` sorts GREATEST and a plain `max` would crown a timestamp-less row "oldest"; `None` when no member is dated), and `fold` — the single DISPLAY entry point, which reduces a display list to the visible indices plus a head→hidden-count map (it keeps its own keyed map because it must consult `expanded` BY key). It also owns `lost_agent_bindings`, the ONE question that needs a member compared against its own origin: the `session_id`s of background forks that carry an `agent-name` but lost the `agent-setting` their lineage ROOT still holds (anthropics/claude-code#80811). Gated on the root rather than on the bare signature, which over-flags because `agentName` is free-form; O(n) via one grouping pass, and derived per RELOAD, never per row. Presentation-only throughout: it hides indices and badges rows, it cannot drop a session. Pure and framework-free. See [DOMAIN.md](DOMAIN.md#fork-lineage-storelineage) for the mechanism it models and [Lost agent binding](DOMAIN.md#lost-agent-binding-storelineage) for the badge. |
| `store::preview` | `src/store/preview.rs` | Transcript → `RenderedPreview` (styled ratatui `Text` + clickable `LinkRegion`s and `FoldRegion`s + per-turn `MarkerLine`s, plus the `UnindexedRows` search must not mark), self-contained markdown pass; the control-wrapper PARSE it draws from is `store::command`'s. A `● claude` marker carries up to four DIM annotations, in order: the bound-agent handle, the answering model (family + dotted version, via `model_label`, which `send` shares), the effort level (`record_effort`), and the time — see [DOMAIN.md](DOMAIN.md#answering-model-storepreview). The same pass keeps ONE file-level fact beside the per-turn ones, `RenderedPreview::last_model`: the label of the model a `-r` launch without `--model` would restore (the pure `restorable_model` — the newest non-`isMeta` `assistant` record naming a real model, `isMeta` asked through the shared `label::is_meta`), which the quick-reply box reads off this cached render for its default and never re-parses — see [DOMAIN.md](DOMAIN.md#the-model-a--r-launch-restores-last_model). A message handed back by a subagent renders as a PEER NODE — one `◆ message from …` header whose body is drawn only while the node is open — instead of the `▶ you` turn it used to be; membership is decided from the record's own `origin` (`label::peer_origin`) and never from the `<agent-message …>` text frame (shape and rationale: [DOMAIN.md](DOMAIN.md#peer-message-node-storepreview)). Context Claude Code INJECTED (`label::is_injected` — a skill body, a caveat) renders as an INJECTED NODE, `◇ added by claude code`, through the same fold machinery, tried AFTER the peer gate because every hand-back also carries `isMeta`; an open one's body is reported as an `UnindexedRows` run (shape: [DOMAIN.md](DOMAIN.md#injected-context-node-storepreview)). A node's `FoldRegion` carries its fold key — `origin.from` for a peer node, the record `uuid` behind an `injected:` prefix for an injected one — and `render` READS the caller's open set as a 4th argument beside `known_agents` — it stays pure and never owns the set. Every region kind is rebased by the ONE `rebased` pass (over the private `BlockRegion` trait), so a node, the links inside its body and its unindexed rows can never disagree about a row. The markers are the turn marker `Line`s captured during the SAME pass, addressed in the same content-row space as a link region and rebased by the same running line offset, so the pinned banner can show the marker of whichever turn the viewport's top row lands on without deriving a second copy of that text. A fold node — peer or injected — contributes NO marker: it is not a turn, and its header's click affordance is a promise the pinned row could not keep, so the banner goes on naming the turn above it. |
| `worktrees` | `src/worktrees.rs` | **Which project a directory belongs to**, answered two ways because `Scope::Project` needs both. (1) The launch project's LIVE worktree set — the **only** place `snapback` shells out to `git` (`git -C <launch_dir> worktree list --porcelain`, argv built by the pure `git_worktree_argv`). (2) `project_root`, the canonicalized repo root of any path, built on the store's pure `group::repo_root_of` — the arm that still answers for a REMOVED worktree, which git structurally cannot. `project_root` derives the prefix from the RAW path and canonicalizes only THAT; the reverse order silently breaks a symlinked prefix under a missing leaf, which is exactly the case it exists for. `project_root_name` is the one place the "git resolved no label" fallback name is written, shared by the group head and the header so a project cannot be called two things on one screen. Sits OUTSIDE `src/store/*` on purpose: the store's grouping core stays a pure string heuristic, so the git answer is launch context (like the launch dir) resolved here and handed to the TUI. A TOP-LEVEL module, not a `tui` child, so the dependency runs one way — `tui` → `worktrees` → `store::group` — with no cycle. Owns `resolve_dir`, the canonicalization every RUNTIME comparison goes through — a session `cwd`, a git-reported worktree root, and the launch dir once `App` holds it — so membership is always decided in one resolved form; it moved here from `tui::app` so the resolver cannot depend on the TUI. Not literally the only `canonicalize` call in the crate: `cli::launch_dir` canonicalizes the process cwd once at startup, before `App` exists, with the same fall-back-to-raw behavior, and two calls answer questions that are not membership — the watcher canonicalizes its watch root (notify reports canonical paths), and `model_aliases` the `claude` binary it is about to read. Fail-soft toward "could not resolve": a missing `git`, a non-repo dir, a non-zero exit, non-UTF-8 output, or unparseable text all yield an EMPTY `WorktreeSet` — a meaningful answer, not an error (see [DOMAIN.md](DOMAIN.md#user-facing-modes-tuiapp)). Output is captured into pipes with stdin null, so git can never write to the board's terminal. |
| `search` | `src/search.rs` | The **only** place `memchr` is called: substring index, incremental re-filter, both marking seams. Per keystroke the filter answers MEMBERSHIP with `memchr::memmem` over prebuilt haystacks — no UTF-32 conversion, no ranking (`App::order_filtered` owns display order). Smart case is decided per ATOM, selecting the cased or lowercased haystack, and every lowercased string here — the filter's and both marking seams' — goes through the ONE per-char, byte-length-preserving fold. In name+content mode a MULTI-atom AND is bounded to a proximity window rather than plain co-occurrence. ONE mechanism, TWO rules, split by what the surface IS: `match_indices` answers for the list row's LABEL under the WHOLE-STRING rule — one string, every atom in it, which is why the row is there at all — while `atom_match_positions` marks the preview's rendered lines PER ATOM, because the transcript is many strings and the filter admitted it on atoms occurring ANYWHERE in it. Both run the SAME per-atom finders, so the label marks every occurrence of an atom rather than one chosen run. The preview asks per RENDERED line rather than mapping a `content_index` position into the pane, which is not a thing that can be done (see [DOMAIN.md](DOMAIN.md#a-content-index-position-never-projects-into-preview-coordinates)). `nucleo` appears only in this file's `mod tests`, as the parity oracle. |
| `agents` | `src/agents.rs` | Agent detection via `claude agents --json`, read TWO ways through ONE fail-soft parser. `reported_agents` (`--all`, polled off-thread every `watch::AGENTS_REFRESH`, 5s, skipped while the board is idle — see [DOMAIN.md](DOMAIN.md#why-the-gate-does-not-read-the---all-map)) is the DISPLAY signal: `classify` buckets each qualifier into an `AgentActivity` that the list row's translated qualifier (via `qualifier_copy`, which the pinned preview banner reaches ONLY through its fallback for a transcript with no marker at all and through the status a LIVE agent's pinned turn marker carries), list-badge color and pulse (which alternates that color, never the glyph) derive from. `live_agents` (bare, NO `--all`) is the HAND-OFF signal, taken one-shot at EVERY hand-off — the resume/attach gate and the `Ctrl-R`/`Ctrl-K` gates alike — and its records also carry the short job `id` that `claude attach`/`claude stop` take, and the `pid` that `Ctrl-K`'s signal route takes when there is no job id. `ReportedAgent` parses `pid` and `startedAt` fail-soft (`name` was dropped for having no reader), each with NAMED consumers: `pid` → `send::interrupt_gate`'s signal route, the only reader of its VALUE, read only off the bare probe, plus the pinned preview row's live test (`view::reports_live_process`), which reads only its PRESENCE off the polled map — and never the delete guard; `startedAt` → the preview banner's age, via the pure, clock-free `elapsed_phrase` (see [DOMAIN.md](DOMAIN.md#reported-agents-srcagentsrs)). Why the two readings must never be merged, and why an authoritative decision never reads the polled map, is [DOMAIN.md](DOMAIN.md#why-the-gate-does-not-read-the---all-map) — do not restate it here. Framework-free: it interprets the value set, while the color it maps to is the view's call. |
| `defined_agents` | `src/defined_agents.rs` | DEFINED-agent discovery for a new session: fail-soft frontmatter scan of `~/.claude/agents/*.md` + `<launch_dir>/.claude/agents/*.md`, deduped (project over user). Distinct from `agents` (live vs. defined). |
| `model_aliases` | `src/model_aliases.rs` | The `--model` alias set the INSTALLED `claude` accepts, read out of that binary at RUNTIME so the compose model picker (`Ctrl-L`) is not a compile-time capture that rots on every claude release (`claude --help` cannot be the source — it names three of the nine). Split exactly like `agents`: pure `parse_model_aliases` is the SINGLE interpreter of the byte format (a flat, minified array literal), which selects by CONTENT ANCHOR — `opusplan`, carried by no sibling array — with longest-wins only as a deterministic tie-break, and NEVER by the minified identifier holding the array, which is regenerated on every build. The impure `installed_model_aliases` walks `$PATH`, canonicalizes the hit (that entry is a symlink into a versioned store, so without canonicalizing there is no saying WHICH version was read) and chunk-reads the ~290 MB non-UTF-8 file with an overlap window sized from the same cap the extractor enforces, so no match can straddle a chunk boundary unseen. FAIL-SOFT to an EMPTY vector on every branch — no `PATH`, no binary, a failed canonicalize, an unreadable file, a read error, no match — which callers read as "keep the seed", never as an error to handle. Uses NEITHER `nucleo` NOR `memchr` (MATCHER ISOLATION) and caches in a process-lifetime `OnceLock` with no disk write at all (SNAPBACK-OWNED STATE); both rule conflicts are resolved and argued in the module's own docs rather than by amending a rule. A plain blocking fn in `agents::reported_agents`' shape — it knows nothing about threads or events, and must never be called on the render path. |
| `claude_settings` | `src/claude_settings.rs` | What `claude` decides about the model when snapback sends no `--model`, read the way `claude` reads it (verified against the 2.1.282 bundle — see [CLAUDE_CLI.md](CLAUDE_CLI.md#which-model-a-launch-runs-on-without---model)): the two answers the compose boxes' `model:` labels need, returned together as `ModelDefaults { new_session, restore_overridden }` from ONE read of the settings layers. Pure `resolve_new_session_model` owns a NEW session's model — a draft's default — over already-read file contents and the env value. Pure `resolve_restore_overridden` owns whether a `-r` launch would SKIP restoring the session's own model (a `RESTORE_OVERRIDE_ENV` name resolves to a NON-EMPTY value by CLAUDE_CLI.md's rule, so an empty settings `env` entry masks a set process variable), which turns a reply's default into plain `default`. Pure `settings_layer_paths` pins which files are read in which precedence, and pure `drop_in_order` the managed drop-in filter and sort — the rules all four mirror are CLAUDE_CLI.md's, not restated here. The thin impure `model_defaults` reads the environment and the files (through `defaults_from_disk`, whose locations and environment are parameters so the suite reads a temp dir) and delegates both decisions. FAIL-SOFT throughout, toward `None` / `false` ([PATTERNS.md §1](PATTERNS.md#1-fail-soft-over-external-input) owns the direction). Lives OUTSIDE `src/store/*` (the store stays pure) and outside `config` (which resolves snapback-OWNED paths only); the `.claude` dir name is `defined_agents::CLAUDE_DIR`, shared rather than respelled. Deliberately does not mirror the MDM/server-managed tiers, the global config's `env`, or `claude`'s git-root relocation of `settings.local.json`: a miss there mislabels a compose box and never changes what `claude` runs, since with no pick snapback sends no `--model` (the label's other known limits are [DOMAIN.md](DOMAIN.md#compose-model-pick-ctrl-l)'s). A plain blocking fn in `model_aliases`' shape — never on the render path. |
| `watch` | `src/watch.rs` | Debounced FS watcher + `EventLoop` that merges input/watcher/tick/agents onto one channel, plus TWO one-shot reads: the `--model` alias probe (`spawn_model_alias_probe` over `spawn_model_alias_thread`), a thread that delivers a single `AppEvent::ModelAliases` and then ends, and the settings-model read (`spawn_settings_model_probe` over `spawn_settings_model_thread`), which delivers a single `AppEvent::SettingsModel(ModelDefaults)` the same way — each a seam that takes its probe as a PARAMETER, so the suite states an answer instead of walking a 290 MB binary or reading the machine's real settings. The watcher classifies each debounce batch against BOTH halves of the shape rule `store::discover` owns — `store_depth` for WHICH LEVEL a path sits at, `is_session_path` for whether it is a session — and reloads only when the batch is not provably irrelevant (`classify_watch_path` / `batch_needs_reload`), so an irrelevant write elsewhere in the store root never triggers a reload. The agents poller backs off to `AGENTS_REFRESH` (5s) and skips the `claude agents` shell-out once the board-activity stamp is older than `AGENTS_IDLE_AFTER` (60s) — see [DOMAIN.md](DOMAIN.md#reported-agents-srcagentsrs). It stamps each map with the WALL-CLOCK instant it was answered (`wall_clock_ms`, the thin wrapper over the pure `epoch_ms`) and sends the pair as `AppEvent::ReportedAgents { agents, reported_at_ms }`; that stamp is epoch millis and is never mixed with the monotonic `now_ms` the idle gate reads. |
| `resume` | `src/resume.rs` | Resume/fork/attach/new-session hand-off: re-read authoritative parts (or, for a new session, gate on the launch dir + optional `--agent <name>`), existence gate, spawn `claude`, return. Resume and Fork (`build_argv(session_id, fork)`, gated by `check(session, fork)`) and Attach (`build_attach_argv`, `check_attach`) take NO model parameter; of the hand-offs only a New session's `build_new_argv`/`check_new` take a `ModelPick` (the rule is AGENTS.md's, the per-launch table [DOMAIN.md](DOMAIN.md#compose-model-pick-ctrl-l)'s). The pick's optional effort is written as `--effort <level>` right after `--model` and only inside its guard, by the ONE `push_model_flag` that `build_new_argv` and the two `send` builders share, with the levels kept in the one `EFFORT_LEVELS` const. Each `Ready` carries its own non-zero hint: the neutral resume or new-session wording, or — picked by `nonzero_hint_for` — `MODEL_NONZERO_HINT`, which NAMES the draft's pick as a likely cause, whenever a New launch actually emits the flag. |
| `config` | `src/config.rs` | The SINGLE place that reads the environment to resolve snapback-owned paths: `config_dir()` (`$SNAPBACK_CONFIG_DIR` else `~/.config/snapback` — deliberately non-XDG on macOS, so one greppable home on every OS) and `state_dir()` (`<config>/state`, where `hidden` persists). ## Runtime architecture

### The persistent-dashboard loop (`lib::run`)

`run` owns the `App` (and the one `SessionStore`) across the whole session and
calls `tui::run(&mut app, &mut store)` in a loop:

- `Outcome::Quit` → break.
- `Outcome::Resume(ready)` → `tui::run` has already torn the terminal down;
  `resume::launch` spawns `claude` as a **child** that inherits the TTY, waits
  for it, then the store is reloaded and the loop calls `run` again (which
  re-initializes the terminal). Quitting the resumed `claude` drops the user
  back onto the board — `snapback` never replaces its own process image.

A **non-zero** child exit routes through `after_nonzero_resume`. On the
plain-resume path only (`Ready::race_probe_id` is `Some`; every other hand-off is
structurally excluded), it re-probes claude: if the session is live NOW, the
resume lost the liveness race, so the board says so and opens the Attach/Fork
overlay, which persists on the `App` into the next `tui::run`. Otherwise the
plan's neutral hint stands — the board never claims a session is running on
anything but the probe's word, and it never parses claude's error text (stdout
and stderr belong to the child; see the terminal-safety seams).

### The elm-style board (`tui`)

`tui::run` → `run_inner` initializes the terminal, builds an `EventLoop`, and
loops: `terminal.draw(view::render)` then `events.recv()` →
`update::handle_event`. `App` is pure state; `view` reads it (and writes back
layout-derived values like pane rects, scroll offsets, and viewport height so
mouse hit-testing and paging work without the model knowing the layout). A
left-click in the preview — resolved on the button's RELEASE, since only then is it
known not to be the start of a drag-selection (a drag's release — or a
double-click's second one — copies the selection instead, and toggles or opens
nothing) — is mapped screen→content in
two halves. The ROW is
resolved EXACTLY on BOTH paths, through the same cached per-line prefix map the
windowed draw starts from (`view::line_at_row`, the one place a wrapped row becomes
a logical line), so a fold and a link can never disagree about which line a click
landed on. The COLUMN is where they part. `view::fold_at` takes the character-packed
answer from the private `view::content_hit` — enough there, since a `FoldRegion`
claims its header's whole display width — and toggles the fold node — a peer
message or injected context — in place.
`view::link_at` resolves the CELL exactly instead, by re-rendering the line with a
candidate `LinkRegion` marked and reading the clicked cell back out of an in-memory
`Buffer` (`view::region_paints_cell`) rather than by modelling where the private
wrapper broke; a hit is opened off the render loop via `resume::open_url` AND
reported as a transient `opening <url>` status, which is the only thing separating a
missed hit from an opener that failed silently. A MISS writes no status, so it
cannot evict an unread sticky refusal; an unwritten cell is admitted only as a wide
glyph's second half, never as the blank tail of a row, so a click on empty space
opens nothing.

**An idle board still repaints every `TICK` (250 ms), and that is an ACCEPTED,
DEFERRED cost — not an oversight.** The loop draws *before* every `recv()`, so
each `AppEvent::Tick` costs one full render whether or not anything could have
changed. The tick itself has to keep arriving (`App::tick` is the board's only
clock: `view::blink_visible` phases the badge pulse off it, `App::tick_status`
ages transient statuses on it, and `update::replay_undelivered` settles on it a
quick reply that finished across a hand-off), so the saving would have to come
from deciding per event whether the next frame can differ from the last — a real
change, with a real way to be wrong, and nobody has asked for it. Do not "fix" it
in passing.
The idle work that WAS removed is the `claude agents` shell-out
([event source 4](#event-sources-watcheventloop)), which is a `claude` child per
cycle rather than a diffed repaint.

### Event sources (`watch::EventLoop`)

Six producers merged onto one `mpsc` channel of `AppEvent` — four recurring, and
two single-shot reads:

1. **Input** — a crossterm reader thread (`AppEvent::Input`) that polls with a
   timeout so it can observe a shutdown flag; joined on `EventLoop` drop so the
   reader releases stdin **before** `claude` is spawned onto the same fd. It
   forwards every crossterm `Event` variant verbatim, so what `tui::update`
   routes is decided entirely there — keys, mouse, and (since `init_terminal`
   enables bracketed paste) `Event::Paste`, the whole clipboard drop in one event
   rather than a stream of keystrokes.
2. **Watcher** — a recursive `notify` watch over the store root, debounced
   ~200ms; an entire settle batch coalesces to one `AppEvent::SessionsChanged`
   — but only once the batch is filtered through `classify_watch_path`
   (`watch::batch_needs_reload`). That classifier re-uses the store's own shape
   rule whole rather than re-deriving it: `store::discover::store_depth` says
   which LEVEL the path sits at (`Root` / `CwdLevel` / `SessionLevel` /
   `BelowSession` / `Outside`) and `store::discover::is_session_path` says
   whether it is the depth-2 `.jsonl` discovery consumes. The level is what
   metadata is then allowed to widen: a batch whose paths are all provably
   outside the shape (below the session level, or a proven non-session
   file/dir at or above it) is dropped before the store ever reloads, while
   anything uncertain (missing metadata, a `CwdLevel` entry that is not
   provably a file, the root itself, a path outside the root) falls through to
   reload rather than risk missing a real change.
3. **Tick** — a ~250ms `AppEvent::Tick` that drives redraw/autorefresh
   visibility (does nothing costly) and advances `App::tick`, the board's only
   clock — `view::blink_visible` phases the live-badge pulse (a color swap, via
   `view::pulse_color`) and the search cursor off it. After aging the status
   line it also replays any quick-reply completion an earlier board session could
   not read (one lock-and-take; see below). It NEVER touches the
   board-activity stamp the agents poller reads (below) — a `Tick` alone must
   never keep the board "active" forever.
4. **Agents poller** — an off-UI-thread `claude agents --json --all` poll every
   `watch::AGENTS_REFRESH` (5s), ONE call per cycle, delivering
   `AppEvent::ReportedAgents { agents, reported_at_ms }` (the map plus the
   wall-clock instant it was answered, which the banner's age is measured
   against), so the shell-out never blocks rendering. Once the
   board-activity stamp (touched only by input events and emitted
   `SessionsChanged`) is older than `watch::AGENTS_IDLE_AFTER` (60s), the poller
   skips the shell-out but keeps sleeping on the same interval, so the first
   activity after idle resumes polling within one cycle. Like the reader it
   observes `EventLoop`'s shutdown flag once per turn — at the TOP, ahead of the
   idle gate — so it is bounded to the board session even while idle, when it
   sends nothing that could notice a dropped receiver. Unlike the reader it is
   NOT joined, so teardown never waits on a `claude` child: it outlives the
   request by up to one cycle plus whatever shell-out that turn had already
   begun. It feeds badges/banner only; the resume gate's liveness probe is a
   separate one-shot at hand-off and is NOT an event source
   (see [PATTERNS.md](PATTERNS.md#6-off-ui-thread-for-anything-that-can-block)).
5. **Model-alias probe** — a ONE-SHOT, not a poller, started once per board
   session beside the agents poller (`EventLoop::spawn_model_alias_probe`). It
   reads the installed `claude`'s `--model` alias set off the UI thread
   (`model_aliases::installed_model_aliases`), delivers exactly one
   `AppEvent::ModelAliases`, and its thread ends. Sending once and returning is
   why it needs no shutdown flag: the bounding problem the flag exists for belongs
   to LOOPING producers that can accumulate one thread per resume round trip, and
   a thread that cannot loop cannot accumulate. Nothing waits on it — the
   compose model picker (`Ctrl-L`) draws its compile-time seed until the answer lands, and keeps
   the seed if it never does — which is what lets a scan measured at ~125 ms
   release / ~2.2 s debug sit on the same channel as the render loop. Per BOARD
   SESSION rather than per process on purpose: the scan itself is memoized in a
   `OnceLock`, so a later session re-delivers rather than re-reads, and
   re-delivering is what stops a probe still in flight across a resume hand-off
   from losing its answer to the receiver that hand-off dropped.
6. **Settings-model read** — the second ONE-SHOT, started beside the alias probe
   once per board session (`EventLoop::spawn_settings_model_probe`, handed
   `App::launch_dir`). It resolves, off the UI thread and from the user's
   `claude` settings files and environment, the model a NEW session would get and
   whether an `ANTHROPIC_MODEL` / `ANTHROPIC_DEFAULT_*_MODEL` override stops a
   `-r` launch restoring the session's own model (`claude_settings::model_defaults`),
   delivers exactly one `AppEvent::SettingsModel(ModelDefaults)`, and its thread
   ends — no shutdown flag, for the same reason as the probe above. Unlike the
   probe it is NOT memoized: a board session begins at launch and again on every
   return from a `claude` child, and re-reading there is the point, since a
   `/model` pick saved as the default inside that child is exactly what the next
   draft's label must pick up. Nothing waits on it: until the FIRST read lands the
   compose boxes read `App`'s empty seed (`settings_model: None`,
   `restore_overridden: false`) — a draft says `model: default`, a reply names its
   session's model — and on a later board session the previous answer stands
   until the new one replaces it (`App` outlives the board session).

Four more NON-recurring producers join on demand, all via `EventLoop::sender` and
all one-shot per keypress rather than pollers, so the render loop never blocks on
the child:

- a confirmed quick-reply send (`Ctrl-R`) fires `send::spawn_send` on a detached
  thread that runs `claude -p -r <id>` to completion and delivers exactly ONE
  `AppEvent::SendFinished`;
- a confirmed interrupt (`Ctrl-K`) fires `send::spawn_interrupt` the same way for
  `claude stop <job-id>`, delivering exactly ONE `AppEvent::InterruptFinished`;
- a confirmed background-agent launch (`Enter` in the new-session draft pane) fires
  `send::spawn_bg_launch` for `claude [--agent <name>] [--model <alias> [--effort <level>]] --bg <prompt>`
  (the model only when that draft picked one), delivering exactly ONE
  `AppEvent::BgLaunchFinished`. It is keyed by no SESSION — a brand-new
  agent has no `sessionId` yet, and the agent itself arrives through the watcher
  reload — but it IS keyed by its own dispatch: `App::dispatch_draft` mints a
  board-local `launch_id`, the `BgLaunchRequest` carries it out and the event
  carries it back, and `App::launching_draft` is what decides whether the card on
  screen is still that launch's to close. That single event is what ends the card
  the dispatch left standing, so the in-flight placeholder needs no clock of its
  own;
- a clipboard copy — `Ctrl-X y`'s session id, or a finished preview drag's
  selection — where the route has a clipboard tool (a local macOS or Linux
  desktop) fires `tui::clipboard::spawn_tool_copy`, which pipes the payload's
  text into `pbcopy`, `wl-copy`, or `xclip` then `xsel`, and delivers exactly
  ONE `AppEvent::CopyFinished { payload, copied }`. With no tool to try (SSH,
  no display, another OS) nothing is spawned: the driver writes the OSC 52
  fallback at once.

`Ctrl-K`'s signal route is deliberately NOT a fifth producer. A confirmed,
re-verified `Outcome::Signal { pid }` is one non-blocking `kill(2)` that the
driver performs inline and reports straight to `App::status`, so it has no
thread, no event and nothing that could outlive the board session.

All four are **emitted** exactly once, spawn failures included — but emitted is
not delivered, and the difference is bounded by the board session. `run_inner`
builds a NEW `EventLoop` per board session and drops the old receiver at every
hand-off, while `lib::run` re-enters the board on the SAME `App`; a child still
running across that seam reports into a channel nobody reads. The four events
are treated differently at that seam:

- **`SendFinished` is CARRIED across it.** The watcher reload brings the reply's
  text in, but only this event clears the reply's `App::sending` entry (its own
  session's, and no other). That entry keeps `Ctrl-X d` refusing a transcript the
  child may still be writing (`delete::can_delete_target`), and it keeps `Ctrl-R`
  from sending that same session a second reply. So a lost completion used to
  strand both until restart. Clearing the entry at the seam instead would reopen
  the delete while the child still writes. One
  `send::UndeliveredEvents` queue per `App` carries the event instead:
  - the send thread queues it when its send fails (`deliver`);
  - `run_inner`'s teardown moves one the dying channel ACCEPTED but never read
    into the same queue before the receiver drops (`drain_then_drop`). Both
    steps run under the queue's lock, so no completion can fall between them;
  - the next board replays the queue through the ordinary `SendFinished` arm
    (`update::replay_undelivered`), once at entry before the first draw and on
    every `Tick` after `tick_status`.

  The replay rides the existing tick, so no thread, clock or event source is
  added.
- **`InterruptFinished` is still dropped there.** Losing it costs only its status
  message: `App::interrupting` is an identity guard with no visible label.
- **`CopyFinished` is dropped there as well**, and strands nothing: no status
  claims a copy before its result lands.
- **`BgLaunchFinished` is still dropped too**, but the draft card is UI state
  waiting on it, so it cannot be left to one that may never arrive:
  `update::handle_event` tears the compose surface down on any outcome that
  [ends the board session](#the-persistent-dashboard-loop-librun) — `Quit` and
  every `Resume` — which bounds the card to the board that dispatched it.

### The load pipeline (`store`)

`discover` (depth-pinned, subagent-excluding) → **reuse or** `parse` (fail-soft,
per file in parallel via rayon) → derive (`label`, `repo`, timestamp,
`root_uuid`, `msg_count`, `content_index`, `failed_task`) → sort repo↑ / branch↑ /
timestamp↓.
Every correctness constraint lives here and is covered by unit tests. See
[DOMAIN.md](DOMAIN.md) for the data model and
[the incremental reload](DOMAIN.md#incremental-reload-storesessionstore) for what
the reuse step may and may not decide.

**Discovery runs in full on every reload; only PARSING is incremental.** That
split is the whole safety argument: the cache answers what a discovered file
CONTAINS, so its worst failure is a briefly stale row, and it is structurally
incapable of the failure that would matter — a session on disk that never
reaches the board. The new cache is rebuilt from the discovered set rather than
edited, so a deleted file's entry leaves with it.

`root_uuid` and `msg_count` both fall out of the SAME streaming pass — no second
read, no walk, no index — which is why the lineage needs no cache of its own and
why the turn count costs nothing to keep. `failed_task` does too: its set/clear
decision is order-dependent, and the pass already walks the records in file
order. `msg_count` is counted OUTSIDE the
`CONTENT_INDEX_CAP` guard on purpose: inside it, the count would stop with the
buffer (see [DOMAIN.md](DOMAIN.md#turn-count-storeparse)). `store::lineage` then
runs **above** this pipeline, at display time (`App::recompute_filtered`), never
during the load: folding is a view of the store, not part of it.

Every reload lands in ONE funnel, `App::apply_reload`, and that is also where
the launch project's worktree set is **re-resolved** (`worktrees`, above) before
`recompute_scope` runs — so `Scope::Project` picks up a worktree created mid-run
without a restart, and a reload is scoped by the current set rather than one
reload behind it. The funnel needs no wiring at its callers: the
`AppEvent::SessionsChanged` watcher reload, the post-resume reload in `lib::run`,
the post-delete reload and the `Ctrl-X r` forced rescan all already go through it
(the three `tui` ones via `update::reload_board`), so a future reload path
inherits the same behavior. `apply_sessions` is the same funnel entered from a
session list that did not come through the store cache — it states "assume every
row moved" — and is what tests with synthetic sessions call. The set is resolved
at exactly two moments — construction and reload — and NEVER in
`recompute_scope` / `toggle_scope`, which run on a keystroke.

The `Reload` the funnel receives also names the sessions the store actually
re-read, and that is what lets the derived caches survive a reload: the preview
cache evicts only those entries (plus any whose session left the board) and
`SearchIndex::refresh` reuses the rest on its own fingerprint. Clearing either
wholesale would re-render every transcript the board touches at the watcher's
cadence and spend the saved parse one layer up.

The single `SessionStore` is owned by `lib::run` and threaded into `tui::run` →
`update::handle_event`, replacing the store root that used to travel there: the
cache is keyed by paths under one root, so root and cache are one value and
cannot drift onto different trees. Threading it (rather than rebuilding one per
reload) is also what makes the launch load warm the cache the board then reloads
against.

### Terminal safety seams

`tui::init_terminal` enters the alt screen + raw mode, wraps ratatui's panic
hook to also disable mouse capture **and bracketed paste**, then enables those
two modes. `restore_terminal` is idempotent, disables both, and runs on **every**
exit — clean quit, error, resume hand-off, and panic — so the user's shell always
gets a clean terminal back. This is what makes the resume round trip and
re-initialization safe.

Bracketed paste (`CSI ?2004h`) is enabled for a specific reason: it makes
crossterm deliver a clipboard drop as one `Event::Paste` instead of a keystroke
stream in which the first embedded newline reads as `Enter` — which sent a quick
reply's first line, closed compose, typed the rest into the search query, and let
a later newline hit the board's resume binding. Enabling it is therefore what
`tui::update` routes against; the ownership obligations that come with turning a
mode on are the TERMINAL SAFETY rule in [AGENTS.md](../../AGENTS.md).

The **return** leg is defended symmetrically: `run_inner` calls `hard_reset`
before the first draw. `init_terminal` re-enters the alt screen + raw + mouse
capture + bracketed paste on every board (re)entry, but cannot recover a terminal a returning `claude` child
left dirty: its `EnterAlternateScreen` is a no-op when the emulator already
believes it is on the alt screen, and the diff renderer only repaints cells that
differ from its freshly-built buffer. `hard_reset` is therefore a deterministic
full re-init that asserts ONE complete return-to-known-state rather than clearing
one mode per reported bug — it (1) recovers the terminal's escape parser FIRST,
before any other escape, with a write-only `CAN` (`0x18`) + `ST` (`ESC \`) + SGR
reset (`CSI 0m`): a child that exited MID control-string (a dangling DCS/OSC/CSI
with no terminator) leaves the parser swallowing input, so were the re-init
escapes to run ahead of the recovery they would be eaten as string content and
every downstream SGR code would render as literal text (the reported leaked
`[39m` cascading over the board); (2) returns keyboard/cursor/minor-mode state to
a known-good baseline — pops the kitty keyboard progressive-enhancement stack
(`CSI < 1 u`) AND absolute-disables its flags (`CSI = 0 u`), resets the cursor
shape (`CSI 0 SP q`) and shows it (`CSI ?25h`), soft-resets remaining minor DEC
modes (`DECSTR`, `CSI ! p`), and forces normal cursor keys (`DECCKM`-off,
`CSI ? 1 l`); (3) confirms raw mode; (4) disables input modes the child may have
leaked (bracketed paste, focus reporting); (5) round-trips
`LeaveAlternateScreen`→`EnterAlternateScreen` to force a *fresh* alt buffer,
re-arms mouse capture **and bracketed paste**, clears the visible screen with
`Clear(ClearType::All)` (`CSI 2J`), and purges the native scrollback with
`Clear(ClearType::Purge)` (`CSI 3J`). Every escape it emits is **write-only** —
the seam issues NO cursor-position (DSR `CSI 6n`) query.

Steps (4) and (5) are one helper (`reset_child_modes_and_reassert_board`) because
the ORDER between them is a contract, not an accident: bracketed paste is turned
OFF by (4), clearing whatever level the child left, and back ON by (5), the
board's own enable. Reversed, the board returns from every resume with paste
disabled and the keystroke-stream bug silently comes back. Composing them in one
`Write`-generic function is what lets a unit test pin `?2004l` before `?2004h`
against real production code rather than against an order the test chose.

The kitty keyboard reset in step (2) is the priority fix for the reported
*still-unstable* `Ctrl-Z`: a `claude` child that pushed progressive enhancement
and exited without popping leaves an enhancement level active that re-encodes
ordinary keys (release events, alternate reports) and scrambles the board's
input — a mode none of the other seams ever cleared, so it persisted across the
round trip. A single pop clears only ONE stack level and the depth is UNKNOWABLE
without a `CSI ? u` query (a DSR-class query forbidden on this write-only path),
so the seam pairs one pop with an absolute `CSI = 0 u` off — the robust
write-only way to reach "no enhancement" regardless of residual depth; both are
harmless no-ops on terminals lacking the protocol. Step (2) runs BEFORE step (5)
deliberately: `DECSTR` is a soft reset over DEC ANSI modes only
(DECCKM/DECOM/DECAWM/DECTCEM/SGR/…) and does NOT touch the xterm private modes
`?1049` (alt screen) or `?100x` (mouse), so re-asserting those afterwards still
wins — verified in a tmux repro where the board renders and mouse scroll still
work after a dirty `Ctrl-Z` return.

The write-only discipline is deliberate: in ratatui 0.30
`Terminal::clear()` first calls `get_cursor_position()`, which emits `CSI 6n` and
blocks reading the reply; on a dirty `Ctrl-Z` hand-back the reply is lost,
crossterm times out (~2s), and the error crashed snapback with "The cursor
position could not be read within a normal duration". A write-only `2J` is
sufficient because `init_terminal` hands `run_inner` a brand-new terminal with
empty buffers on every board (re)entry, so the first `draw` after the physical
`2J` repaints every cell — no back-buffer reset needed. The `?1049` round-trip
and the `3J` purge are what heal the reported `Ctrl-Z` dirty-exit corruption — a
bare visible-screen `2J` alone left stale cells and native scrollback showing
through — while the `CAN`+`ST`+SGR-reset prefix heals the related `Ctrl-Z`
variant where the child exits mid control-string and the board's own escapes
render as literal text. The recovery bytes are harmless no-ops on a clean
terminal, so they are prepended unconditionally on every board (re)entry. `CAN`
and `ST` have no crossterm typed command — nor do step (2)'s kitty/DEC escapes
(`CSI = 0 u`, `DECSTR`, `DECCKM`-off), each a named `const` byte array for the
same reason — so this seam is one of only TWO narrow spots the codebase writes
raw control bytes (the second is the OSC 52 clipboard write below). Anything that
DOES have a typed command uses it (the SGR reset does); the "never embed ANSI
escapes" styling rule governs `view.rs`/`preview.rs` presentation, not terminal
parser recovery here.

The **second** write-only raw-escape site is `tui::clipboard::copy_to_clipboard`,
and it is the clipboard copy's FALLBACK, not its route — for `Ctrl-X y`'s id and a
preview drag's selection alike. The copy goes through the OS clipboard tool
first: on a local session the driver starts a worker thread that pipes the text
into `pbcopy` on macOS, or `wl-copy` / `xclip` / `xsel`
on Linux, and that worker never touches the terminal (see `tui::clipboard` in the
module map). The escape is written only when no tool can do it: over SSH (a
local tool there would fill the REMOTE machine's clipboard, while OSC 52 reaches
the user's own terminal), with no tool for the OS or display, or when every
candidate was missing or failed. Its one runtime caller is `update::finish_copy`,
which the driver (`run_inner`, directly or through `start_copy`) runs on the UI
thread with `io::stdout()`, in the event-handling phase BETWEEN draws. It is
never called from the worker, whose write could interleave with a frame the UI
thread is flushing. It is the same shape as the `hard_reset` exception — raw
bytes with no crossterm typed command — but narrower: it emits ONE
`ESC ] 52 ; c ; <base64(text)> BEL` OSC 52 set-clipboard escape and nothing else.
Being write-only it moves no cursor, mutates no cells, and NEVER emits the
OSC 52 `?` query form — a DSR-class query is forbidden here exactly as on the
return leg, since it would block reading a reply — so it is safe to emit
mid-session: the next `terminal.draw` diffs against an unchanged screen and
repaints nothing, and there is no reply to block on.

OSC 52 support is uneven and the write-only discipline forbids asking whether
the escape landed, so the status is HONEST about which route ran:
`Copied session ID <uuid>` / `Copied selection (N lines)` only when a clipboard
tool exited 0 with the text on its stdin, and `Sent session ID <uuid> …`
(`update::osc52_sent_status`) / `Sent selection (N lines) …` on the escape path,
which never say "Copied"; the id's line puts the id ahead of its caveat so a
narrow help row cuts the caveat, not the id. The id's lines are STICKY — cleared
by the next key, never by the dwell timer — while a selection's expire, and
[PATTERNS.md](PATTERNS.md#11-status-line-ownership) owns why.

A preview drag-selection adds NO third raw-escape site. Its release hands the
selected text to `Outcome::Copy`, and it reaches the terminal, if at all, through
this same `copy_to_clipboard` — there is no second OSC 52 writer to keep in step.
